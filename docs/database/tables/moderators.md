# `moderators` Table

## Purpose

- Stores standalone CMS moderator login records.
- CMS moderators authenticate with an 8-character login ID and TOTP from an authenticator app.
- This table is not linked to `users`; app users and CMS moderators are separate identities.

## Columns

- `id`: `BIGSERIAL`, primary key, auto-increment, not null.
- `login_id`: `CHAR(8)`, not null, unique; must match `^[A-Za-z0-9]{8}$`.
- `role_id`: `BIGINT`, not null, foreign key to `moderator_roles.id`.
- `display_name`: `VARCHAR(120)`, not null.
- `email`: `VARCHAR`, nullable; editable from CMS profile, validated as email format, and enforced unique by the CMS app among active/non-deleted moderators.
- `profile_photo_url`: `TEXT`, nullable; optional CMS profile photo URL/path for moderator profile display. Current CMS uploads store local paths under `/uploads/moderators/...`.
- `totp_secret_encrypted`: `TEXT`, nullable; encrypted TOTP secret generated by the CMS portal during first-login setup.
- `totp_enabled_at`: `TIMESTAMPTZ`, nullable; set only after the moderator verifies the first authenticator code.
- `is_active`: `BOOLEAN`, not null, default `TRUE`.
- `last_login_at`: `TIMESTAMPTZ`, nullable.
- `created_at`: `TIMESTAMPTZ`, not null, default `CURRENT_TIMESTAMP`.
- `updated_at`: `TIMESTAMPTZ`, not null, default `CURRENT_TIMESTAMP`.
- `deleted_at`: `TIMESTAMPTZ`, nullable (soft delete marker).

## Keys And Constraints

- Primary key: `id`.
- Unique constraint: `login_id`.
- Check constraint: `moderators_login_id_format` enforces 8 alphanumeric characters.

## Foreign Keys

- `role_id -> moderator_roles.id`.

## Indexes

- `idx_moderators_role_id` on `role_id`.
- `idx_moderators_active_login_id` on `login_id` where `is_active = TRUE AND deleted_at IS NULL`.

## Seed Data

- Migration `000027` inserts one active `super_admin` moderator with a generated 8-character `login_id`.
- The seeded super admin has no TOTP secret initially. On first CMS login, the portal shows a QR code, stores the encrypted pending secret, verifies the first authenticator code, then sets `totp_enabled_at`.
- Retrieve the seeded login ID:

```sql
SELECT m.login_id
FROM moderators m
JOIN moderator_roles r ON r.id = m.role_id
WHERE r.code = 'super_admin'
  AND m.deleted_at IS NULL
ORDER BY m.created_at
LIMIT 1;
```
